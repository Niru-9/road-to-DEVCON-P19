```text
A Merkle proof is a way to verify that a transaction is part of a block without having to download the entire block. It consists of a hash tree, where each leaf node represents a transaction hash, and each non-leaf node is the hash of its child nodes. To prove a transaction's inclusion, you need to show that the transaction's hash is part of the path from the root to the leaf representing that transaction.

When verifying, you start at the root and follow the path to the leaf. This path is a sequence of hashes, and you can use these hashes to construct a Merkle proof. The proof includes the transaction's hash and the hashes of the nodes along the path from the leaf to the root. By recomputing the hash of the nodes along this path, you can confirm that the transaction's hash matches the leaf node, thus proving the transaction's inclusion in the block.
```

### What the measurements do and do not mean

The system prompt above is the deterministic output of `buildSystemMessage()` for that
profile, and this script asserts it byte-for-byte against an independently computed prompt.
That is the part this repository is responsible for.

Whether the configured model provider then obeys a style rule is a property of that provider.
The measurements are printed so a reader can see the difference instead of taking it on trust,
and so a judge can point at a case where a small local model ignored a preference. Swapping
`LLM_BASE_URL` / `LLM_MODEL` for a stronger provider is the intended fix for that; no part of
the recorded evidence depends on a particular provider obeying the rules.
